All of the configuration files for Cobblemon Boosters are located in the `<game_directory>/config/cobblemon_boosters/` directory.

**Configuration files:**
- `core.toml` - This file contains the core configuration options for Cobblemon Boosters.
- `permissions.toml` - This file contains the permission nodes for Cobblemon Boosters.
- `webhooks.toml` - This file contains the configuration options for Discord webhooks. This file is only used if the `matthiesen_core_webhooks` mod is installed.
- `cache.toml` - This file contains cached data for the boosters. It is automatically generated and should not be edited manually.
- `text.toml` - This file contains the text messages and GUI configuration for Cobblemon Boosters.

## Core Configuration

```toml title="core.toml"
#General Configuration
[general]
	saveIntervalTicks = 600
	verboseCacheLogging = false
	displayMode = "BOSSBAR"
	queuePriorityEnabled = true
	queuePriorityMode = "FIFO"
	timePriorityDirection = "SHORTEST_FIRST"
	activePreemptionEnabled = false

```

### General Configuration

#### saveIntervalTicks

The interval in ticks at which the server saves data. The default value is 600 ticks (30 seconds). This value must be greater than 1.

- Default Value: `600`

#### verboseCacheLogging

Enables or disables verbose logging for the cache. When enabled, the server will log detailed information about cache operations.

- Default Value: `false`

#### displayMode

Specifies the display mode of the boosts for the server.

**Allowed Values:**
- `BOSSBAR`
- `SIDEBAR`
- `NONE`

- Default Value: `BOSSBAR`

#### queuePriorityEnabled

Enables or disables the queue priority system. When enabled, boosts will be processed based on the specified priority mode.

- Default Value: `true`

#### queuePriorityMode

Specifies the mode for queue priority. This determines how boosts are prioritized in the queue.

**Allowed Values:**
- `FIFO` - First In, First Out
- `MULTIPLIER` - Prioritize based on the multiplier value
- `TIME_REMAINING` - Prioritize based on the remaining time of the boost

- Default Value: `FIFO`

#### timePriorityDirection

Specifies the direction for time-based priority when `queuePriorityMode` is set to `TIME_REMAINING`.

**Allowed Values:**
- `SHORTEST_FIRST` - Prioritize boosts with the shortest remaining time
- `LONGEST_FIRST` - Prioritize boosts with the longest remaining time

- Default Value: `SHORTEST_FIRST`

#### activePreemptionEnabled

Enables or disables active preemption in the queue. When enabled, new boosts can preempt currently active boosts based on the priority settings.

- Default Value: `false`

### Command Permissions

**Allowed Values:**
- `NONE` - No permission required to use the command.
- `SPAWN_PROTECTION_BYPASS` - Requires the player to have the spawn protection bypass permission to use the command.
- `CHEAT_COMMANDS_AND_COMMAND_BLOCKS` - Requires the player to have the cheat commands and command blocks permission to use the command.
- `MULTIPLAYER_MANAGEMENT` - Requires the player to have the multiplayer management permission to use the command.
- `ALL_COMMANDS` - Requires the player to have the all commands permission to use the command.

#### reload

The permission level required to use the `/boosters reload` command. This command reloads the booster services.

- Default Value: `ALL_COMMANDS`

#### clear_queues

The permission level required to use the `/boosters clear-queues` command. This command clears all queued boosts.

- Default Value: `ALL_COMMANDS`

#### check_queues

The permission level required to use the `/boosters check-queues` command. This command checks the status of all queued boosts.

- Default Value: `ALL_COMMANDS`

#### queue_priority

The permission level required to use the `/boosters queue-priority` command. This command manages the queue priority settings.

- Default Value: `ALL_COMMANDS`

### Discord Webhooks Configuration

#### enabled

Enables or disables Discord webhooks for booster events. When enabled, the mod will send notifications to the specified Discord webhook URL for various booster events.

- Default Value: `false`

#### webhookUrl

The Discord Webhook URL to send booster event notifications to. This should be a valid Discord webhook URL.

- Default Value: `DISCORD_WEBHOOK_URL_HERE`

#### discordAuthorName

The name to display as the author of the Discord webhook messages. This is the name that will appear in the webhook message.

- Default Value: `Cobblemon Boosters`

#### discordAuthorIconUrl

The URL of the icon to display as the author of the Discord webhook messages. This should be a valid URL to an image.

- Default Value: `https://raw.githubusercontent.com/Matthiesen-Dev/cobblemon-boosters/refs/heads/main/assets/logo.png`

## Cache Configuration

```toml title="cache.toml"
#Boosters Cache
#This file should not be edited manually
[cache]

	#Active Boosts
	[cache.activeBoosts]
		#The currently active Shiny Boost, serialized as a string
		activeShinyBoost = ""
		#The currently active Catch Boost, serialized as a string
		activeCatchBoost = ""
		#The currently active Experience Boost, serialized as a string
		activeExperienceBoost = ""
		#The currently active Spawn Bucket Boost, serialized as a string
		activeSpawnBucketBoost = ""

	#Queued Boosts
	[cache.queuedBoosts]
		#The queued Shiny Boosts, serialized as a list of strings
		queuedShinyBoosts = []
		#The queued Catch Boosts, serialized as a list of strings
		queuedCatchBoosts = []
		#The queued Experience Boosts, serialized as a list of strings
		queuedExperienceBoosts = []
		#The queued Spawn Bucket Boosts, serialized as a list of strings
		queuedSpawnBucketBoosts = []
```

### Cache Configuration

Unlike the other configuration files, the `cache.toml` file is automatically generated and should not be edited manually. It contains cached data for the boosters, including the currently active boosts and the queued boosts.

If needed, the cache file can be cleared manually, and it will be regenerated automatically in an empty state. However, it is recommended to use the `/boosters clear-queues` command to clear the cache instead of manually editing the file.

#### activeBoosts

The `activeBoosts` section contains the currently active boosts for Shiny, Catch, Experience, and Spawn Bucket. Each boost is serialized as a string and represents the current state of the boost.

#### queuedBoosts

The `queuedBoosts` section contains the queued boosts for Shiny, Catch, Experience, and Spawn Bucket. Each boost is serialized as a list of strings and represents the boosts that are waiting to be activated.

### Text Parser

#### textParser

Specifies the parser used to format configured messages. Existing messages may need to be updated when changing parsers, because each parser supports different formatting codes.

**Allowed Values:**
- `VANILLA` - Uses vanilla Minecraft formatting codes.
- `EMBERS` - Uses the formatting supported by the Embers parser.
- `ADVENTURE` - Uses Adventure MiniMessage formatting.

- Default Value: `VANILLA`

### Spawn Bucket Configuration

The `spawnBuckets` section sets the display names used for each spawn bucket. These names are inserted into GUI text and boost messages.

- `common` - Display name for the common bucket. Default: `Common`
- `uncommon` - Display name for the uncommon bucket. Default: `Uncommon`
- `rare` - Display name for the rare bucket. Default: `Rare`
- `ultraRare` - Display name for the ultra-rare bucket. Default: `Ultra Rare`
- `boss` - Display name for the boss bucket. Default: `Alpha`

### GUI Configuration

The `gui` section customizes menu titles, button labels, and other text shown in booster GUIs. Text values use the format supported by `textParser`. Values containing `%s` or named placeholders retain those placeholders so the mod can insert the relevant name, value, or page number.

#### Main GUI

- `mainMenu_unknownBoosterType` - Message shown if the main menu encounters an unknown booster type.
- `CheckQueues_title` - Title of the queue overview GUI.
- `stopActiveBoost_title` - Confirmation title shown before stopping an active boost.
- `baseTitle` - Base title used by booster GUIs.
- `text_nextPage` and `text_previousPage` - Labels for page navigation.

#### Admin GUI

The `gui.adminGui` section sets the menu title and confirmation titles for the reload and clear-queues actions: `title`, `button_reloadTitle`, and `button_clearQueuesTitle`.

#### Booster Builder

The `gui.boosterBuilder` section customizes the builder title, field labels, and confirmation text. The title accepts `%booster_name%`; the current mode, multiplier, duration, boost type, bucket, and unit values use `%s` for the value supplied by the GUI.

- `boosterBuilder_title`, `boosterBuilder_mode_current`, and `boosterBuilder_mode_notSet` - Builder title and mode status text.
- `boosterBuilder_noValue` - Text shown for a field that has not been set.
- `boosterBuilder_multiplier`, `boosterBuilder_duration`, `boosterBuilder_boostType`, `boosterBuilder_bucket`, and `boosterBuilder_unit` - Labels and values for the corresponding boost settings.
- `boosterBuilder_details` - Details label.
- `boosterBuilder_label_multiplier`, `boosterBuilder_label_duration`, `boosterBuilder_label_unit`, and `boosterBuilder_label_bucket` - Button labels for selecting builder fields.
- `boosterBuilder_confirm_title` - Confirmation title for starting or queueing the boost.

#### Queue GUI

The `gui.queueGui` section configures the queue title and the duration and bucket labels. `queue_title` uses `%s` for the queue name; `queue_duration` and `queue_bucket` use `%duration%` and `%bucket%` respectively.

#### Booster Titles

The `gui.boosterTitles` section contains a title, display name, and menu title for each booster type: `catch`, `experience`, `shiny`, and `spawnBucket`. The catch, experience, and shiny titles accept `%multiplier%`; the spawn bucket title accepts `%bucket%`.

#### GUI Buttons

The `gui.buttons` section configures button labels and their text colors. Each `*_color` value must be one of the Minecraft text colors listed in the TOML comments. The label keys are:

- `confirmBoost`, `boostQueueEntry`, and `viewBoostDetails` - Boost confirmation, queue entry, and details actions.
- `increment` and `decrement` - Value adjustment actions.
- `spawnBucketBoosters`, `shinyBoosters`, `catchBoosters`, and `experienceBoosters` - Booster category buttons.
- `viewQueue` and `viewQueue_multiple` - Queue buttons; each uses `%s` for the queue name or count.
- `adminMenu`, `reloadConfig`, and `clearAllQueues` - Admin actions.
- `cancel`, `confirm`, `stopActiveBoost`, and `viewActiveBoost` - Confirmation and active-boost actions.
- `startBoost` - Start action; uses `%s` for the booster name.
- `pageText` - Page indicator; uses `%s` for the current page and total page count.

Each label's matching `*_color` key controls its color. The sample values are the defaults.

### Messages Configuration

The `messages` section configures chat messages and boost display text. Message strings can use the configured text parser and the placeholders shown in the sample. `prefix` is substituted wherever `%prefix%` appears, and `sidebarTitle` sets the sidebar display title.

- `commandReload` - Confirmation sent after reloading the booster services.
- `queuePriorityStatus` - Queue-priority status output; uses `%s` for the current settings.
- `queuePriorityUpdated` - Confirmation after a queue-priority setting changes; uses `%s` for the updated setting.

#### Boost Messages

The `shinyMessages`, `catchBoostMessages`, `experienceBoostMessages`, and `spawnBucketBoostMessages` sections each configure one boost type. They share the following settings:

- `barColor` and `barOverlay` - Boss bar color and overlay style. Allowed values are listed in the TOML comments.
- `barText` and `sidebarLine` - Text shown in the boss bar or sidebar while the boost is active.
- `noActiveBoosts` and `noQueuedBoosts` - Messages shown when there are no active or queued boosts of that type.
- `boostStarted` and `boostAddedToQueue` - Messages shown when a boost starts immediately or is added to the queue.
- `boostStopped` and `boostQueueCleared` - Messages shown after stopping a boost or clearing its queue.
- `boostInfo` - Status details for a boost.

The message templates use `%multiplier%`, `%duration%`, `%time_remaining%`, `%time_remaining_short2%`, and `%bucket%` as appropriate for the boost type. Their default colors, text, and formatting are shown in the corresponding TOML entries.

#### Error Messages

The `messages.errorMessages` section customizes validation and command feedback:

- `unknownBoostType` - Shown for an unrecognized boost type; `%s` is replaced with the valid types.
- `invalidMode` and `invalidDirection` - Shown when an invalid queue mode or time direction is provided.
- `selectModeFirst` - Shown when a setting requires selecting a field first.
- `missingFields` - Shown when required builder fields are missing at confirmation.
